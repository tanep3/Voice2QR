# Voice2QR 要件・決定事項

状態： 要件確定（2026-11-14）。開発は Muse が専用の VM で行い、コードと文書は GitHub コネクタ経由で tanep3/Voice2QR へ push する。この文書（`docs/requirements.md`）は Voice2QR の要件と決定事項の正本であり、用語と数値を自己完結で記す。Notion の同名ページは閲覧用コピー。

# 1. これは何か

- 本人の声そのものを QR コードに記録し、読み取ればネットワークなしでその場で再生できるアプリ／データフォーマット。
- 仕組み： 声 → Codec2 で符号化 → そのバイナリを QR コードのバイトモードに直接格納 → 読取時に Codec2 で復号して再生。
- Codec2 とは： 声を波形としてではなく「声の特徴パラメータ」として記録する音声コーデック（ボコーダ）。電話音声級の帯域で設計され、1,200 bps という極低レートでも本人の声として聞き取れる。オープンソースで特許フリー。
- テキスト＋読み上げ（TTS）方式は不採用。録った声をテキスト化した時点で、それは録音ではなく再演であり、本人の声は消えるため。
- 起点： 高校時代、「音をデータに変換すれば劣化せず保存できるはず」と考え、カセットテープへ A/D 変換記録を試みた Tane の体験。DAT（PCM）→ MP3 でも届かなかった 2,400 bps 級の帯域に、ボコーダなら声そのものが入る、というのが本プロジェクトの核。

# 2. 決定事項（方式）

| 項目 | 決定 | 理由 |
| --- | --- | --- |
| 音声コーデック | Codec2、**1200 bps** | 特許フリー・オープンソース。2400 bps は誤り訂正 M では約7.7秒で QR 容量を超過するため、紙用途では不採用 |
| QR 誤り訂正レベル | **M**（復元力 約15%） | 紙への印刷を前提に耐久性優先 |
| 記録時間 | 1個の QR で最大 **約15.5秒** | 誤り訂正 M のバイトモード容量 2,331 バイトから算出 |
| サンプリング | 8 kHz モノラル固定 | Codec2 の対象帯域 |
| データ形式 | QV フォーマット（§3） | PC／スマホ両アプリの共通契約 |
| QR 描画 | モジュール整数倍拡大、アンチエイリアスなし | 印刷時の再現性。補間してぼかさない |
| ネットワーク | 不使用 | 全処理を端末内で完結させる |

# 3. QV フォーマット v1

詳細仕様は `docs/format.md`。ここでは要約のみ記す。

QR のバイトモードに以下をそのまま格納する。Base64 等のテキスト化はしない（容量が約33%無駄になる）。

- ヘッダ（7バイト固定）
  - magic： 2バイト、ASCII "QV"（0x51 0x56）
  - version： 1バイト、現在は 1
  - bps： 2バイト、リトルエンディアン。Codec2 のビットレート（例： 1200）
  - frames： 2バイト、リトルエンディアン。後続フレーム数
- データ： Codec2 フレームを時間順に連結。1200 bps では 1フレーム = 40 ms = 6バイト。
- 復号手順： 先頭が "QV" でなければ Voice2QR データではない。bps と frames を読んでデコーダを初期化し、フレーム列を順に復号して 8 kHz PCM として再生する。
- bps フィールドにより他モードも同形式で格納できるが、印刷用途の標準は 1200 とする。
- 将来拡張（v1 の範囲外）： 15.5秒超は QR の Structured Append による連結。メタデータは QR 内に持たない（容量優先）。タイトル等は印刷時に QR の外へ人間可読テキストとして併記する。

# 4. アプリ要件

構成は「1つのフォーマット＋1つのコア、顔が2つ」。先に作る顔は未決（Tane の判断待ち）。

## 4.1 両アプリ共通

- 機能： 録音、QR 生成、QR 読取、音声再生。
- QR 読取は2経路とも必須： (a) 画像ファイルからの読取、(b) カメラによるライブ読取。
- QR 出力は2経路とも必須： (a) 画面表示、(b) 画像ファイルとして保存。保存画像が印刷の原稿になるため、描画は整数倍拡大・補間なしで鮮明に。

## 4.2 PC アプリ（工房）

- 録音／音声取込、QR 生成・画像保存、アーカイブ管理。
- 印刷： CUPS 経由で感熱プリンタへ直接印刷する。想定機は Phomemo M02S（300 dpi）。印刷基盤は既存の CUPS＋IPP 構成（phomemo-tools）を使う。
- 読取： 画像ファイル＋Web カメラ。

## 4.3 スマホアプリ（現場の機械）

- **完全スタンドアロン。ネットワーク機能を持たない。** 録音・符号化・生成・読取・復号・再生のすべてを端末内で行う。Android では INTERNET 権限なしで実装できる想定（必要な権限はマイク、カメラ、写真のみ）。
- 印刷はアプリ内に実装せず、OS の共有機能で QR 画像を Phomemo アプリへ渡す方式を第一とする。
- 読取： カメラ＋保存済み画像。

# 5. 印刷ガイドライン

- 目安： 1モジュールあたり **3ドット以上**。
- 標準ケース（1200 bps、8.6秒、訂正 M）は QR バージョン30、クワイエットゾーン込み145モジュール。
  - M02S（300 dpi、53 mm幅 ≒ 626ドット）： 約4.3ドット／モジュール
  - T02（203 dpi、384ドット）： 約2.7ドット／モジュール
- クワイエットゾーン（周囲4モジュール）を必ず確保する。

# 6. ライセンスと運用

- 配布： GitHub（tanep3/Voice2QR）で **MIT**。事業目的はない。自前コードの著作権表示は「© 2026 Tane Channel Technology」（pic2gray4px と同形式）。
- Codec2 は **LGPL-2.1** の別コンポーネント。**無改造**で、動的リンク／別ライブラリ（Android では別 .so）として利用する。自前コードに取り込まない。Codec2 の COPYING（LGPL-2.1 本文）と帰属表示を同梱する。静的リンクで単一バイナリに一体化しないこと（LGPL の再リンク可能性の条件を避けるため）。Codec2 自体を改造した場合は、その部分は LGPL で公開が必要。
- その他の部品： segno（BSD）、zxing-cpp（Apache-2.0）など寛容ライセンスのみ。
- 名称は「Voice2QR」に決定（2026-11-14）。当初案「QRvox」は同名の既存アプリと衝突するため不採用。「紙声 Kamigoe」も候補に挙がったが、国際的に伝わらないため見送った。X2Y 表記は自身の pic2gray4px と同じ命名の系譜。データフォーマット名とマジック「QV」は、検証フィクスチャとの互換性のため変更しない。
- 開発分担： 開発は Muse が専用の VM で行う。VM から git コマンドでの直接 push はできないが、GitHub コネクタの push 機能でコードと文書（テキストファイル）を tanep3/Voice2QR へ反映できる（1回ごとに Tane の承認。ファイルの削除はこの経路では扱えない）。バイナリや画像は送れないため、成果物（APK 等）は GitHub Actions（CI）で生成し、README のサンプル QR 画像のような単発のバイナリは Tane が手で追加する。前提（完了）： Tane が tanep3/Voice2QR を作成し、Muse の GitHub App の対象に追加済み（2026-11-14）。初回 push（ライセンス一式・README・QV フォーマット仕様・スパイク一式）も同日完了。資料の正本は本ファイル（`docs/requirements.md`）。Notion のコピーは閲覧用、Google Drive「ChatGPT/Voice2QR」のミラーは補助（仕様共有用）。

# 7. 実証済み（2026-11-14 スパイク）

Muse の VM で方式検証を完了。パイプライン全通：

- サンプル音声（VOICEVOX 波音リツ、8.64秒、8 kHz モノラル）→ Codec2 符号化 → QR 生成 → 生成画像を読み戻して **バイト列完全一致** → 復号した PCM も **完全一致**。Tane が聴取し「しっかりと聞き取れる」と確認。
- 実測値（1200 bps）： ペイロード 1,303バイト（音声 1,296＋ヘッダ7）→ QR バージョン30（訂正 M）。10秒の場合はバージョン32。
- 参考（2400 bps）： 同音声で 2,599バイト → バージョン38（訂正 L）。訂正 M では収まらない。
- スパイクのコードは本リポジトリ `spike/` にある。検証フィクスチャのバイナリ実物（原音声、QR 画像、復号音声、比較画像）は Muse の VM が正本で、`fixtures/` には説明のみを置く。実装の照合（ゴールデンテスト）に使える。
