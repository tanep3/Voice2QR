# QV フォーマット仕様（Voice2QR） v2

Voice2QR が QR コードに格納するバイナリデータの形式。PC アプリとスマホ
アプリの間の契約であり、両者はこの仕様に対して実装する。

ステータス： v2 を正本とする（2026-11-14 決定）。v1 は同日のスパイク
（`spike/`）でのみ使われた未リリース形式であり、マルチメディアへの
拡張を考慮して、リリース前に v2（セクション構造）へ置き換えた。

## 1. ペイロード全体

QR コードの **バイトモード** に、そのままペイロードを格納する。
Base64 等のテキスト化はしない（容量が約33%無駄になるため）。
したがって読み取り側は、QR の生バイト列を取得できるデコーダを使うこと。

```
+--------+--------+====================================+
| magic  | ver    | セクション列（§2）                  |
| 'Q''V' | 1 byte |                                      |
+--------+--------+====================================+
```

| フィールド | サイズ | 内容 |
|---|---|---|
| magic | 2 byte | `0x51 0x56`（ASCII "QV"） |
| version | 1 byte | フォーマットバージョン。本仕様は `2` |

ヘッダは合計 3 バイト。以降はすべてセクション（§2）で構成される。

## 2. セクション

ペイロードの残りは、以下のセクションの繰り返しである。すべて可変長。

```
+--------+--------+--------------------+
| type   | length | value              |
| 1 byte | 2 byte | length バイト      |
+--------+--------+--------------------+
```

- `length` は value のバイト数。リトルエンディアン。
- セクションの並び順は任意。ただし書き手は決定的な出力を得るため
  type の昇順に並べること（ゴールデンテストで照合できるように）。
- 読み手はセクションを先頭から順に歩き、知らない type は `length`
  分だけ読み飛ばす。これにより、旧い読み手でも新しいセクションを
  含むデータを壊さずに処理できる。
- `length` がペイロードの末尾を超える場合は、そのデータは不正である。
- VOICE セクション（§3）は最大で1つだけ置く。複数ある場合は
  読み手は先頭のものを採用する。

## 3. セクション種別

| type | 名前 | value の内容 |
|---|---|---|
| `0x01` | VOICE | bps（2 byte、LE）＋ frames（2 byte、LE）＋ Codec2 フレーム列 |
| `0x02` | TEXT | UTF-8 テキスト（終端文字なし） |
| `0x03` | IMAGE | 形式（1 byte）＋画像バイト列。形式： `1` = WebP、`2` = JPEG |
| その他 | 予約 | 読み手は読み飛ばす |

VOICE セクションの value の長さは `4 + frames × frame_bytes` に
一致しなければならない（frame_bytes は bps から決まる。§4）。

## 4. 音声パラメータ

- サンプリング周波数：8 kHz、モノラル、16 bit PCM を Codec2 へ入力する。
- 標準モード：**Codec2 1200 bps**。1 フレーム = 40 ms = 320 サンプル、
  符号化後は 48 bit = **6 バイト**。
- `bps` により他モード（2400 / 1600 / 1400 / 1300 / 700C 等）も
  格納できる。復号側は、生成で使いうる全モードに対応すること。
  ただし印刷用途の標準は 1200 とする（2400 は訂正M では約7.7秒で
  容量超過する）。

## 5. QR コード生成パラメータ

- 誤り訂正レベル：**M**（復元力約15%）。印刷物前提の標準。
- 最大容量：訂正M のバイトモード上限は **2,331 バイト**。
- 音声だけの場合のオーバーヘッドは 10 バイト（ヘッダ3＋セクション
  ヘッダ3＋bps/frames 4）。1200 bps の記録上限は
  (2331 − 10) ÷ 150 ≒ **15.5 秒**。
- バージョンは容量に応じて自動選択（目安：8.6秒で Version 30）。
- 描画：モジュール単位の整数倍拡大とし、補間（アンチエイリアス）を
  行わない。クワイエットゾーン（周囲の余白4モジュール）を確保する。

## 6. 印刷ガイドライン（感熱プリンタ）

- 1モジュールあたり **3ドット以上** を目安とする。
  例（モジュール数＝クワイエットゾーン込み）：
  - 1200 bps / 8.6秒 / 訂正M：145モジュール → M02S（300dpi、53mm幅
    約626ドット）で約4.3ドット/モジュール。T02（203dpi、384ドット）
    で約2.7ドット/モジュール。
- 印刷経路ごとに実機での読み取り率を検証すること（特にスマホアプリ
  から Phomemo アプリへ画像転送して印刷する経路は、転送先の画像処理
  の影響が未検証）。

## 7. 復号手順（読み取り側）

1. QR 画像（カメラ映像または画像ファイル）から生バイト列を得る。
2. 先頭が "QV" でなければ Voice2QR データではない。version が `2`
   でなければ本仕様の対象外とする。
3. オフセット3からセクションを順に歩く。`length` が末尾を超えたら
   不正なデータとして中断する。
4. VOICE セクションがあれば、その bps で Codec2 デコーダを初期化し、
   frames 個のフレームを順に復号して 8 kHz PCM として再生する。
5. 使わないセクション（Voice2QR における TEXT / IMAGE 等）は
   無視する。VOICE セクションが無い場合、そのデータは Voice2QR
   では再生できない。

## 8. Voice2QR での利用範囲

- Voice2QR が生成するのは、ヘッダ＋ VOICE セクションのみの
  ペイロードである。
- TEXT / IMAGE は、このコンテナを土台とする将来のマルチメディア
  形式のために予約されている。Voice2QR の読み手はそれらを安全に
  読み飛ばし、音声だけを再生できなければならない。これが両形式の
  互換契約である。

## 9. 将来の拡張

- 15.5秒を超えるメッセージ：QR の Structured Append による連結を
  検討。
- 新しいセクション種別は、version を上げずに追加できる（読み手が
  未知の type を読み飛ばすため）。既存セクションの意味を変える
  場合は version を上げる。
